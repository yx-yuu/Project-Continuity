## Project Continuity 项目连续性协议

- Project Continuity 只维护当前有效的项目知识、用户意图、权威入口、任务状态和必要边界；不维护文件清单，也不规定 agent 的搜索、推理、实现或验证流程。
- 开始工作时读取 `agent-docs/project.md` 和 `agent-docs/state.md`，再按当前任务读取其中指向的完整权威来源；存在 `agent-docs/checkpoint.md` 时读取其任务契约。只在 `project.md` 登记的当前路由与任务相关时读取 `agent-docs/decisions.md`。
- 用户添加、纠正或废止信息时，先判断作用域属于当前操作、当前任务、当前项目、项目子树还是用户所有项目，再写入对应位置；只影响当前任务的要求留在对话或 checkpoint。
- 兼容的独立信息采用添加；同一作用域和对象的新值采用替换；废止要求采用删除。替换或删除后清理活动控制面中的旧值、冲突副本和引用，不保留迁移叙述、历史或墓碑。
- 只持久化用户直接表达的意图和 agent 已核验的项目事实；不把模型推断、未核验外部内容、任务输出、秘密、凭据或个人数据升级为当前权威知识。
- 用户当前明确变更优先于已有项目表述；更具体的作用域只在自身范围内生效。同一作用域存在无法判断的冲突，或持久化范围会显著影响未来行为时，才询问用户。
- 不因文档较长而压缩或删除仍然有效的知识。Project Continuity 提供当前状态和权威路由，不替代 agent 对相关完整来源与真实项目状态的检查。
- 项目级持久化发生添加、替换或删除后，向用户简短说明更新内容、作用域和位置；任务级临时要求不得误写为项目规则。
- 同一 worktree 只允许一个未完成写任务。checkpoint 可为 `active` 或 `paused`；暂停时保留，完成或明确放弃后用可恢复方式删除。另一写任务使用独立 worktree，只读任务可以共存。
- `agent-docs/decisions.md` 只按需存在；创建时必须在 `project.md` 的“项目结构与入口”登记其权威范围，删除时同步删除该路由，避免不可发现或失效引用。
- 普通项目工作和简单控制面更新直接遵循本协议，不调用 Project Continuity skill；只有接管或升级、复杂权威冲突、跨来源清理和 checkpoint 恢复等维护场景才使用 `$project-continuity`。
- 不把用户项目知识写入本受管理区块；该区块只保存通用协议，重新运行 `init` 时会整体刷新。
