# 当前项目控制协议

research-harness 是由 agent 维护的轻量项目控制面。它保存当前研究定义、稳定约束、目录职责、当前状态和一个可选任务契约；它不维护文件清单、文件快照、任务数据库或自动工作流。

## 不变量

1. 当前上下文只包含仍然有效的信息。
2. 同一对象只有一个当前权威位置，新信息核验后直接替换旧信息。
3. agent 自行选择检查和执行方法，但不能绕过项目约束、证据门禁、任务范围和完成条件。
4. 同一 worktree 只允许一个活动写任务；不同写任务不能共用 checkpoint。
5. 项目结构按目录职责管理。必要文件可在任务中引用，但不形成长期 inventory。

## 核心入口

| 文件 | 职责 | 生命周期 |
|---|---|---|
| `AGENTS.md` | agent 共用的最短协议和恢复入口 | 永久，保持简短 |
| `CLAUDE.md` | Claude Code 导入 `AGENTS.md` 的适配 | 使用 Claude Code 时保留 |
| `project.md` | 当前研究定义、范围、约束和目录职责 | 稳定信息变化时替换 |
| `state.md` | 当前阶段、焦点、下一步、阻塞和证据门禁 | 状态变化时替换 |
| `checkpoint.md` | 一个未结束写任务的契约与恢复状态 | 按需创建，完成后删除 |
| `decisions.md` | 忘记后可能重复犯错的最少决策 | 按需创建，失效后删除 |

默认恢复只读取 `AGENTS.md`、`project.md` 和 `state.md`；存在 checkpoint 时再读取它。不要把完整对话、文件清单、实验流水或历史任务写入控制面。

## Agent 职责

agent 根据仓库和任务选择 Git、搜索、测试、实验工具或领域 skill，直接核验真实材料。代码、数据、结果和论文仍以各自当前来源为准；控制文档只保存稳定边界、当前状态和路由信息。

任务输出、模型推断和外部材料在核验前都是 candidate。信息生效前检查相关目录、实验结果、论文主张和其他下游对象，然后替换对应当前信息。

## 轻量边界

建议保持 `AGENTS.md` 受管理区块不超过 24 行，`project.md` 不超过 180 行，`state.md` 和 checkpoint 各不超过 120 行。超过时优先删除重复、历史、过程和权威来源副本，不拆出更多默认读取文件规避限制。
