# 项目控制生命周期

## 当前信息更新

```text
外部材料或任务输出
  → agent 核验约束、证据和完成条件
  → 检查相关目录与下游对象
  → 替换当前权威信息
  → 删除过时上下文，或因复现/审计/合规需要移出默认读取范围
```

不要长期保存 `candidate`、`stale` 或 `superseded` 区域。未确认信息留在原始来源或当前任务 checkpoint，不升级为项目事实。

## 更新触发

| 事件 | Agent 维护动作 |
|---|---|
| 研究定义、范围或稳定约束变化 | 更新 `project.md`，检查当前状态和下游研究对象 |
| 主要目录新增、删除或职责变化 | 更新 `project.md` 的目录职责与影响关系 |
| 当前阶段、焦点、阻塞或证据门禁变化 | 替换 `state.md` 对应内容 |
| 关键或跨阶段写任务开始 | 确认没有冲突任务后创建一个 checkpoint |
| 跨会话继续同一任务 | 读取并覆盖同一个 checkpoint，不创建历史版本 |
| 新写任务与 checkpoint 冲突 | 先完成、放弃或隔离旧任务，不覆盖旧任务契约 |
| 任务完成 | 核验结果和影响，更新当前信息，再删除 checkpoint |
| 关键决定必须长期记住 | 按需创建或更新 `decisions.md` |

## 删除判断

默认删除同时满足以下条件的内容：不再是当前权威来源、没有当前依赖、不是唯一复现或审计证据、没有合规保留要求，也不包含防止重复犯错的唯一理由。实际删除使用平台可用的可恢复机制。

## 从 0.5 及更早版本迁移

重新运行 `research-harness init` 只刷新 `AGENTS.md`、`CLAUDE.md` 并补齐 `project.md`、`state.md`，不会扫描或删除项目文件。

旧版的 `.research-harness.json`、`.research-harness/`、`agent-docs/index.md`、`bootstrap.md`、`claims.md` 和 `tasks/` 都只是迁移候选。先把仍有效的项目定义、目录职责、状态或决策合并到当前权威文件，再决定是否用可恢复方式删除。旧 `.gitignore` 中由 harness 管理的 `.research-harness/` 规则可在本地状态清理后一起移除。
