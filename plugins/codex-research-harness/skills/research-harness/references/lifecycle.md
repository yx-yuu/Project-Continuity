# 项目控制生命周期

## 信息状态转换

```text
外部材料或任务输出
  → candidate
  → 约束与证据核验
  → 识别并处理受影响对象
  → replace current information
  → 接受新文件基线
  → 旧内容删除，或因复现/审计/合规需要移出默认上下文
```

`stale` 和 `superseded` 只能作为清理过程中的临时判断，不能成为长期堆积区。

## 更新触发

| 事件 | 维护动作 |
|---|---|
| 用户改变项目级约束 | 更新唯一权威位置，标记受影响的代码、实验、结果和论文 |
| 关键、长程或跨阶段任务开始 | 建立一个含范围、完成条件、验证边界和影响对象的 checkpoint |
| 研究定义或范围改变 | 替换 `project.md` 中受影响部分，并检查当前状态与论文主张 |
| 当前阶段、焦点、阻塞或证据门禁改变 | 替换 `state.md` |
| 作出以后仍需记住的决定 | 在 `decisions.md` 写最小记录 |
| 手动加入、修改或移除文件 | 运行 `sync`，确认角色和影响后才登记或接受 |
| 任务完成 | 核对完成条件，传播实际影响，更新当前来源并接受新基线 |
| compact 或跨会话 | 覆盖同一个 checkpoint，恢复后继续使用，不创建历史版本 |
| 任务完成或放弃 | 无 pending change 后清理 checkpoint；放弃任务可显式强制清理 |

## 删除判断

默认删除同时满足以下条件的内容：

- 不再是当前权威来源；
- 没有当前代码、论文或项目状态依赖；
- 不是唯一复现或审计证据；
- 没有伦理、许可、合同或合规保留要求；
- 不包含必须保留以防止重复犯错的唯一理由。

若只有否决理由需要保留，删除旧正文，在 `decisions.md` 留最短结论。若材料仍需复现或审计，把它移出默认读取范围，不继续登记为当前来源。

## 版本迁移

再次运行 `init` 会更新受管理入口和 manifest，并保留项目定义、状态、决策、来源及用户规则。v0.3 checkpoint 缺少任务契约字段时，`doctor` 会给出 warning；继续该任务时用新格式覆盖，任务已经结束时在确认没有 pending change 后清理。

对于 v0.1 遗留的 `bootstrap.md`、`claims.md` 和 `tasks/`，提取仍有效的当前信息后删除；确有审计价值的内容移出默认上下文。所有实际删除使用 `trash`。
