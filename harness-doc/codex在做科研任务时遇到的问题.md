
1. Codex/LLM 本身的局限：上下文利用不稳定、幻觉、迎合、自我校正能力有限、输出非确定。
2. 科研流程本身的高风险：文献遗漏、数据泄漏、统计误用、选择性报告、方法与实现偏差。
3. 工程治理缺失：没有统一事实来源、变更传播、证据溯源、独立验收和停止条件。

最危险的错误传播链通常是：

```
初始假设偏差
  → 定向文献检索
  → 为既有想法合理化方法
  → 同一个模型编写代码和测试
  → 在偏差实验上选择最好结果
  → 同一个模型解释并撰写论文
  → 流畅文本把上游错误固化为“研究结论”
```

单个环节的错误未必致命，真正危险的是错误跨阶段传递，同时每一阶段都让它看起来更可信。

## 一、Codex 对话与长程任务问题

* 上下文过长后，早期目标、例外条件、否决理由和隐含约束可能被忽略。
* 关键信息即使仍在上下文中，也可能出现“中间位置利用率较差”的问题。长上下文容量不等于所有内容都能被可靠使用。
* 自动或手动压缩对话时，摘要容易保存“结论”，却丢失结论成立的前提、反例、置信度和待验证事项。
* 同一个对话承担整篇论文，容易混入大量已经失效的讨论、日志和临时决策。OpenAI 官方也明确提示：用一个任务覆盖整个项目会造成上下文膨胀，并随时间降低结果质量。
* 新问题可能继承旧问题中的错误假设，形成“上下文污染”。
* Idea、猜想、已验证事实、用户偏好、正式决策和废弃方案没有类型区分，Codex 可能把它们当成同等可信的信息。
* 被否决的方案没有记录否决理由，后续会被重新提出；临时权宜方案也可能逐渐被当成正式架构。
* 文档、代码和当前对话分别保存不同版本的事实，Codex 不知道以哪个为准。
* `AGENTS.md`、用户提示、子目录约束、技能说明和任务文档之间可能冲突，局部指令还可能覆盖全局约定。
* Codex 官方文档说明，`AGENTS.md` 指令链通常每次运行只加载一次；运行中更新文件不一定会改变当前会话行为。
* `AGENTS.md` 默认还有合并大小限制。规则不断累积后，后面的内容可能未被加载，或者整体过长而降低可执行性。
* 任务没有明确的完成条件时，Codex 会自行猜测“做到什么程度”，可能过早结束，也可能无限扩张。
* 小 Bug 容易演变成重构、补测试、清理依赖和文档更新，形成范围膨胀。
* 连续失败时，Codex可能继续在同一思路上修改参数或补丁，没有真正回退到问题定义层重新诊断。
* 没有失败尝试账本时，相同的无效实验可能换一种形式再次执行。
* 工具命令成功不等于任务成功；测试通过不等于研究假设成立；生成了一篇完整文本也不等于论文内容正确。
* 网络失败、页面解析失败、付费墙或搜索工具超时，可能被误解为“没有相关文献”。
* 模型、系统提示、工具和服务端实现发生变化后，同样的对话与输入未必产生相同结果。
* 多智能体或并行任务可能基于不同假设工作，造成重复劳动、文件覆盖和不一致结论。
* Token、时间和调用成本会隐式影响 Codex 的行为，例如提前停止搜索、少做验证，或偏向容易执行的方案。

## 二、Idea 与研究问题构思

* Codex 很擅长生成“看起来像论文 Idea”的内容，但合理、完整和新颖是三件不同的事。
* Idea 可能只是已有研究的重新表述，因为没有真正完成新颖性检索。
* 容易优先生成训练语料中常见、主流、容易发表式表达的方向，忽略不常见但可能更有价值的路线。
* 生成式 AI 可能提高单个方案的表面质量，却使不同研究者的想法趋同，造成研究方向同质化。
* 用户先提出一个想法后，Codex 可能围绕它补充论据，而不是积极寻找它不成立的证据。
* RLHF 模型存在迎合倾向，可能优先给出符合用户预期的回答，而不是最严格的反驳。
* 一旦 Codex 给出第一个完整方案，用户和后续对话都容易被该方案锚定，减少真正的发散探索。
* 容易出现“先有方法，再找问题”：因为某种网络结构或算法热门，反过来寻找可以使用它的任务。
* 研究问题可能不可证伪、过于宽泛，或者结论边界没有明确定义。
* 理论构念与实际可测量变量可能不一致，例如用一个方便计算的指标代替真正想研究的现象。
* 论文目标、工程目标和产品目标可能混淆：提高 benchmark 分数不一定产生新的科学知识。
* 方法的新颖性可能来自复杂组合，而不是清晰的新机制或新认识。
* 缺少“什么结果会否定该 Idea”的预设，任何实验结果都可能被事后解释为支持。
* 没有预先考虑数据、算力、时间、伦理审批和复现条件，导致 Idea 理论上成立但博士阶段无法完成。
* 多次局部增加创新点，可能让论文逐渐失去唯一明确的中心问题。

## 三、文献检索与证据综合

* LLM 可能生成完全不存在的论文、作者、期刊、DOI 或页码。
* 文献真实存在，也可能出现标题、作者、年份、卷期或 DOI 错误。
* 文献存在不代表它支持论文中的具体陈述，这是比“假引用”更隐蔽的错误。
* Codex 可能依据摘要、搜索摘要或二手综述转述结论，没有检查原文的方法、样本和限制。
* 可能把某篇论文对其他工作的描述，当成该论文自己的实验结论。
* 二手引用逐层传播后，原始证据和当前主张之间的关系消失，形成“引用洗白”。
* 搜索词由已有 Idea 决定时，容易只找到支持路线，漏掉不同术语、不同学科或否定结果。
* 单一数据库、单一语言和单一出版类型会造成覆盖偏差。
* 容易忽视灰色文献、负结果、复现失败和不显著结果，进一步放大发表偏差。
* 同一研究的预印本、会议版和期刊版可能被当成多项独立证据。
* 可能引用已经撤稿、被更正或有表达关切的论文。
* 文献状态会变化，但静态论文库和长期记忆不会自动更新。
* 纳入和排除标准在检索过程中发生变化，却没有留下记录，造成选择性纳入。
* 搜索日期、数据库、查询式、筛选过程和排除理由未保存，后续无法复现检索。
* Codex 对相关性排序很流畅，但不等于具备系统综述所需的高召回率和稳定筛选能力。
* 不同会话可能给出不同文献集合，没有稳定的文献主表和去重机制。
* 一篇论文可能同时被标记为“支持”“反对”和“背景”，但没有明确对应的主张。
* 引用在论文文本中存在，最终参考文献表中却缺失，或者参考文献表包含从未使用的条目。
* 检索到的网页、论文附件或仓库说明可能包含间接提示注入，诱导具有工具权限的智能体偏离任务。
* 2025 年一项范围综述发现，LLM 已被用于系统综述的多个阶段，但成熟、充分验证的应用仍然不足，不能把普通对话式检索等同于规范的证据综合。

## 四、方法论与数据问题

* 科学主张与机器学习任务不匹配：模型预测准确不一定证明所声称的科学机制。
* 把相关性结果写成因果结论，或者忽略因果识别所需的假设。
* 目标变量只是理论构念的代理，但论文把代理值直接当成真实构念。
* 指标与研究目标不一致，模型最终优化的是容易度量的代理目标。
* 基线缺失、过弱、实现错误，或者没有代表当前领域水平。
* 新方法和基线使用不同数据、预处理、调参预算、预训练资源或计算量，造成不公平比较。
* 选取有利指标，忽略与结论冲突的指标。
* 数据来源、采集时间、许可、使用范围和修改历史不明确。
* 训练数据与目标总体不一致，样本选择偏差被误认为模型能力。
* 标签质量差、标注者分歧、类别定义变化或标签本身含有研究结论。
* 缺失值、异常值和数据排除方式没有预先定义。
* 训练集和测试集存在重复样本、同一主体、同一时间序列或同源派生数据。
* 在全量数据上完成标准化、特征选择、插补或数据清洗，造成预处理泄漏。
* 使用测试集选择模型、超参数、随机种子或阈值，造成测试集适应。
* 预训练模型可能已经接触 benchmark 或相关数据，形成难以识别的污染。
* 随机划分不符合实际部署场景；应使用时间、主体、站点或领域划分时仍采用随机拆分。
* 缺少外部验证、分布外测试和子群体分析。
* 复杂方法增加了大量设计自由度，使研究者更容易在无意中挑选有利配置。
* 数学定义、符号、张量维度和实际算法可能不一致。
* 消融实验同时改变多个因素，无法确定性能变化来自哪个机制。
* 专有模型、在线 API 或闭源数据源会随时间更新，使方法无法严格复现。
* 没有在实施前冻结研究问题、主要指标、数据划分和分析原则。

## 五、方法与实验代码实现

* 论文描述的是理想算法，代码实现的是经过多次修补后的近似版本。
* 伪代码、公式、配置文件和真实执行路径之间不一致。
* 关键行为依赖库的默认值，但论文和配置都没有记录。
* 相同参数在命令行、配置文件、环境变量和代码常量中重复出现，实际生效值不明确。
* 依赖版本、CUDA、驱动、硬件、编译选项和操作系统差异导致结果漂移。
* 保存随机种子不等于完全可复现，GPU 算子、并行数据加载和第三方服务仍可能非确定。
* 广播、类型转换、精度、设备迁移和维度错误可能不报错，却悄悄改变结果。
* 训练与评估使用了不同的预处理、归一化、tokenizer 或标签映射。
* 错误加载旧 checkpoint、错误数据划分、旧缓存或其他实验的中间结果。
* 异常被捕获后自动回退到默认路径，使实验“成功结束”，但实际没有执行预期方法。
* 测试只覆盖正常路径，不覆盖边界条件、数值稳定性、数据泄漏和科学语义。
* Codex 同时编写实现和测试时，测试可能复现同一个需求误解，形成同源错误。
* 为让测试通过而调整实现，可能过拟合测试，而不是修复真实问题。
* 自动测试通过不等于代码符合仓库约定、可维护或真正解决问题。2026 年 METR 的一项维护者评审发现，约一半通过 SWE-bench Verified 自动测试的样本 PR 仍不会被维护者合并；该研究有明确样本和交互限制，但足以说明“测试通过”不是完整验收标准。
* 多轮补丁留下废弃分支、重复实现、临时开关和失效注释，使后续 Codex 更难理解真实路径。
* 缺少从原始数据到最终结果的一键复现入口。
* LLM 可能推荐不存在的软件包。USENIX Security 2025 的研究在其特定实验中发现，商业模型生成的包名至少有 5.2% 为幻觉，开源模型为 21.7%；这类名称还能被攻击者注册，形成供应链风险。
* 生成代码可能含安全漏洞，同时用户对其安全性更加自信。
* 复制生成代码时，许可证、来源和兼容性可能不可追踪。
* 计算复杂度、显存和时间成本没有进入方法设计，导致实验只能在缩小设置下运行。

## 六、实验设计与执行

* 研究问题、假设、实验和预期判别结果之间没有一一对应关系。
* 方法尚未冻结就开始正式实验，后续修改使早期结果失去可比性。
* 在测试集上反复调参，形成自适应过拟合。
* 只报告最好的随机种子、checkpoint、数据集或提示模板。
* 根据当前结果决定是否继续运行，形成可选停止。
* 看到结果后重新定义假设，即 HARKing。
* 进行了大量模型、指标、子群体和数据集比较，却没有控制多重比较。
* 样本量不足、统计功效不足，或者把重复测量当成独立样本。
* 不同方法使用不同调参次数、搜索空间、训练轮数或计算预算。
* 基线复现失败时仍拿低结果比较，没有使用作者结果或解释差异。
* 只报告均值，没有标准差、置信区间或其他不确定性。
* 随机种子太少，结果差异可能只是随机波动。
* 缺少负对照、随机标签、简单启发式和数据打乱等 sanity check。
* 消融没有保持其他变量不变。
* benchmark 已经饱和、污染或不能代表真实使用场景，却仍将其作为主要结论依据。
* 失败实验、无效配置和负结果被删除，后续无法判断选择过程。
* 运行记录缺少代码版本、数据版本、配置、环境、开始时间和产物哈希。
* 缓存、中断恢复和增量运行可能混合不同版本的结果。
* 结果文件被后续实验覆盖，或者文件名无法区分实验条件。
* 为修复一个小问题运行全套昂贵实验，没有按风险选择验证强度。
* 没有停止条件，导致不断增加种子、数据集、消融和稳健性实验，却不改变结论可信度。
* 算力、时间、能源和资金成本没有被纳入研究决策。

## 七、结果分析与科学图表

* 日志解析、单位换算、样本对齐和聚合代码本身可能有错误。
* 选择每个方法最有利的 checkpoint，而非遵循统一选择规则。
* 把统计显著解释为效果重要，或把不显著解释为两者等价。
* 只报告 p 值，不报告效应量、置信区间和实际意义。
* 由预测性能直接推出因果或机制性解释。
* 宏平均、微平均、按任务平均和按样本平均混用。
* 聚合结果掩盖子群体失败、Simpson 悖论或极端案例。
* 使用 LLM 作为裁判会引入位置、权威、措辞、外观和自身偏好等偏差。
* 同一个模型评价自己生成的文本、代码或方法时，错误不具备独立性。
* ICLR 2024 的研究表明，在没有外部反馈时，LLM 的内在自我校正可能失败，甚至降低原答案性能。因此“再让 Codex 检查一次”不能等同于独立验证。
* 图表坐标截断、不一致尺度、颜色误导或只显示有利区间。
* 表格和图表由人工复制数值，修改实验后没有同步更新。
* 异常结果被简单视为运行错误，没有区分真实失败模式。
* 没有逐样本错误分析、鲁棒性分析和敏感性分析。
* 先看到结果再编写解释，容易产生过于顺畅的事后故事。
* 当前论文中的结果可能并非当前代码、数据和配置生成的结果。

## 八、论文撰写、修改与投稿

* 方法部分写成“应该如何实现”，而不是“实际如何实现”。
* 论文主张超出实验能够支持的范围。
* 同一概念在 Idea、公式、代码和论文中使用不同名称或定义。
* 公式、算法框和代码实现逐渐漂移。
* 摘要、引言、结果和结论强调的贡献不一致。
* 表格、图注和正文中的数字来自不同实验版本。
* LLM 生成的文本语法完整、语气确定，却可能缺乏可检验的具体内容。
* 引用真实论文，但对应句子并不受该论文支持。
* 为增强权威感堆积引用，掩盖证据关系不清的问题。
* 多轮分段生成造成重复、局部矛盾和术语漂移。
* 改写原文时过度贴近来源，产生 patchwriting 或抄袭风险。
* 讨论部分把推测写成事实，或者忽略替代解释。
* 局限性、失败案例和负结果被弱化，以保持论文叙事完整。
* 审稿回复修改了方法或实验，却没有同步更新摘要、图表、附录和代码。
* camera-ready 阶段修改代码后，没有重新确认论文结果仍可复现。
* 没有完整报告数据、环境、超参数、随机性和复现入口。
* AI 使用披露不符合目标期刊或学校政策。
* COPE、ICMJE 和 Nature 均明确指出，AI 工具不能作为作者，最终准确性、完整性、原创性和伦理责任由人类作者承担。
* 不同出版机构对“仅语言润色”和“生成性内容”的披露要求不同，不能使用一条固定规则覆盖所有期刊。
* Nature Portfolio 当前一般不允许生成式 AI 图片用于出版，仅保留有限例外。
* 将未公开论文、审稿稿件、专利 Idea 或合作者材料上传到外部服务，可能违反保密义务。
* 依赖 AI 文本检测器判断学术不端也可能造成误判，不能代替来源、修改和贡献记录。

## 九、跨阶段一致性和溯源断裂

完整流水线中最容易断开的映射包括：

* Idea → 研究问题；
* 研究问题 → 可证伪假设；
* 假设 → 论文主张；
* 主张 → 文献证据；
* 主张 → 方法设计；
* 方法定义 → 公式和伪代码；
* 公式 → 真实代码模块；
* 代码 → 配置与环境；
* 配置 → 具体实验运行；
* 实验运行 → 原始结果；
* 原始结果 → 统计分析；
* 分析结果 → 表格和图；
* 表格和图 → 论文中的结论。

其中任何一个映射缺失，都会产生以下问题：

* 修改方法后不知道哪些实验必须重跑；
* 修改代码后不知道哪些公式和段落需要更新；
* 删除实验后论文仍保留对应结论；
* 图表无法追溯到具体运行；
* 一项结论依赖多个实验，却只更新了其中一部分；
* 同一结果被多个论文版本使用，但来源不一致；
* 负结果和反例没有进入正式知识库，后续被遗忘；
* 不同文档各自成为“事实来源”，没有明确优先级；
* 任务完成状态与研究证据状态混为一谈；
* 本地文件正确，但最终投稿包仍包含旧版本。

这也是你所说的 harness 最应解决的核心部分。

## 十、安全、隐私、知识产权与研究伦理

* Codex 读取网页、论文、README、issue、代码注释和邮件时，可能遭遇间接提示注入。
* OWASP 明确列出了通过代码注释、文档、网页、提交信息和外部文件操纵智能体的风险。
* 具有命令执行权限的智能体可能把恶意文本转化为工具调用、文件修改或数据外传。
* 权限过大时，小的推理错误也可能产生破坏性后果。
* API Key、访问令牌、私有数据和配置可能进入日志、上下文或生成文件。
* 未公开数据、受试者信息、健康数据和其他个人信息可能被发送给第三方服务。
* 对话日志本身可能成为新的敏感数据存储。
* 外部 MCP、插件、包管理器和搜索服务构成额外供应链。
* 代码、数据、模型权重和生成内容可能违反许可证、数据库条款或版权。
* 未经核对使用生成内容，可能造成抄袭或商业秘密泄漏。
* 数据使用可能超出受试者同意或伦理审批范围。
* 方法可能对不同人群、语言或场景产生系统性偏差。
* 双重用途研究可能被 Codex 扩展成不适合公开的实现细节。
* 为复现而公开数据或日志时，可能重新识别个体或泄露内部信息。
* NIST 还将虚构内容、隐私、偏差与同质化、人机配置、信息完整性、安全、知识产权、供应链和环境影响列为生成式 AI 的主要风险类别。

## 十一、人机协作与博士培养风险

* Codex 输出越流畅，人越容易把语言质量误认为推理质量。
* 自动化偏差会使用户在模型看起来可靠时减少独立检查。
* CHI 2025 对知识工作者的调查发现，对生成式 AI 的信心越高，与更少的批判性思考相关；这是一项自报告研究，不能直接推导因果，但说明信任校准是重要问题。
* AI 编码工具的主观提速感可能与客观效率不一致。METR 早期模型的实验中，开发者认为自己被加速，但实际完成时间更长；该结果不应外推到当前工具，却说明“感觉更快”不是可靠指标。
* Codex 生成内容的速度远高于人类审查速度，容易形成审查债务。
* 当修改量过大时，人类只能抽查，最危险的语义错误反而不一定被看到。
* 长期依赖会削弱亲自进行文献判断、实验诊断、统计推理和代码阅读的能力。
* 用户可能逐渐失去对自己系统的完整心智模型。
* 同一个 Codex 负责 Idea、实现、测试、解释和写作，会形成高度相关的错误，而不是五次独立验证。
* 失败后不断投入更多对话和实验，容易出现沉没成本与升级承诺。
* 大量看似完成的产物会制造虚假进度，但真正可发表的证据可能没有增加。
* 人与 AI 之间的责任边界模糊时，容易出现“是模型建议的”这种责任扩散，但出版规范不会接受这种解释。
* 合作者可能不知道哪些内容由 AI 生成、哪些结论经过人工核查，造成团队认知不一致。
* 博士训练的目标不仅是产出论文，还包括形成独立判断能力；若 harness 只追求自动化产出，会与培养目标冲突。

## 十二、harness 自身也可能失败

建立 harness 很必要，但不能把它理解成“多写文档”。它本身也有风险：

* 文档存在不等于 Codex 每次都会读取、正确理解并执行。
* 记录了状态，但没有自动验收和变更触发，仍然只是静态档案。
* 文档不断增长会重新制造上下文膨胀。
* 自动把 Codex 输出写入记忆，可能把幻觉和临时猜测永久化。
* 没有区分事实、假设、决策、证据和废弃内容，记忆库会逐渐失真。
* 过于严格的流程会阻碍早期科研探索，使尚未成熟的 Idea 被过早冻结。
* 一套固定 checklist 不能同时适用于探索、正式实验、调试和投稿阶段。
* 为所有小修改运行完整验证，会重现你已经观察到的“一个小问题引发大量测试”。
* 验收指标本身可能被优化或绕过，例如为了通过测试而偏离研究语义。
* harness 维护成本可能超过它节省的时间，变成新的研究负担。
* 没有明确维护责任和淘汰机制时，旧规则会与新架构冲突。
* 如果 harness 依赖单一供应商、模型或工具版本，服务变化后自身也无法复现。
* 为保证完整审计而保存所有对话和数据，会与隐私、保密和存储成本发生冲突。
* 最终仍需要独立的人类或异构验证源；不能由生成错误的同一模型独自证明自己正确。

因此，更准确的结论是：

> 你需要的不是一个“帮助 Codex 记忆更多内容”的系统，而是一套管理研究状态、证据关系、变更传播、验证独立性、任务边界和人类责任的科研控制系统。

## 当前最优先防范的 12 个问题

如果按可能造成整篇论文失效的严重程度排序，我会优先关注：

1. 方法、代码、实验和论文不一致。
2. 数据泄漏、测试集适应和 benchmark 污染。
3. 文献真实但不支持对应主张。
4. 同一个模型生成实现、测试并自我审查。
5. 图表和结论无法追溯到具体实验运行。
6. 上下文压缩后丢失关键前提和否决理由。
7. 缺少停止条件导致局部问题无限扩张。
8. 测试通过被误认为科学正确。
9. 选择性种子、checkpoint、指标和结果报告。
10. 未记录模型、提示、工具、环境和数据版本。
11. 保密数据、提示注入和软件供应链风险。
12. AI 使用披露、作者责任和知识产权不合规。
