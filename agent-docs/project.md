# 项目定义

- 项目名称：`project-continuity`
- 更新时间：`2026-07-27T11:01:45Z`
- 当前远程仓库：`https://github.com/yx-yuu/Project-Continuity`

## 当前项目目标

如何用结构简单、可版本控制的 Markdown 控制面，让不同 coding agent 持续理解用户对项目的当前意图、完整有效知识、作用域明确的约束和未完成任务状态，同时把搜索、推理、执行与验证方法继续交给 agent 自主决定。

## 当前范围与非目标

- 范围：通用项目协议初始化、跨会话和跨 agent 上下文恢复、用户纠正与项目知识的作用域和生命周期管理、当前状态、每个 worktree 一个可选未完成写任务契约、Codex 插件和可移植 Python CLI。
- 非目标：限制项目知识容量、对有效知识做有损压缩、文件清单或快照、命令链、固定工作流、任务数据库、后台任务、hooks、Git 操作以及替代 agent 的项目检查和执行判断。

## 当前术语与方法边界

- **控制面**：`AGENTS.md`、`CLAUDE.md` 和 `agent-docs/` 中结构简单的 Markdown 入口；可保存完整有效知识，也可路由到项目中其他权威来源。
- **当前项目知识**：用户直接表达的当前意图、约束与纠正，以及 agent 已核验的项目事实；不把未核验推断升级为当前权威信息。
- **作用域**：要求可以只适用于当前操作、当前任务、当前项目、项目子树或用户所有项目；保存位置和生命周期由作用域决定。
- **更新方式**：兼容的独立信息采用添加；同一作用域和对象的新值采用替换；废止要求采用删除；当前控制面不保留旧值、迁移叙述或墓碑。
- **state 与 checkpoint**：`state.md` 只保存项目级阶段、焦点、阻塞和下一步；checkpoint 是当前 worktree 跨会话未完成写任务契约的唯一权威，可为 `active` 或 `paused`，完成或明确放弃后删除。
- **激活机制**：`AGENTS.md` 提供始终可见的轻量判断协议；只有明确的长期记忆要求、跨任务信息变化、会影响后续任务的已核验稳定事实、需要跨会话恢复的项目阶段或未完成任务状态变化、checkpoint 生命周期变化才触发持久化判断，普通任务和简单控制面更新不需要 skill。
- **信息准入与应用**：项目权威知识只持久化用户直接表达的意图和 agent 已核验的项目事实；`state.md` 可额外保存项目级操作状态和一个下一步，checkpoint 可额外保存任务契约和一个任务级下一步，但这些状态不得升级为项目知识；只读取和应用作用域覆盖当前任务且会实质影响当前判断的信息。
- **意图与事实**：用户期望的目标状态和 agent 核验的项目当前事实是不同对象；用户新表述只替换同一作用域的旧用户意图，真实项目状态决定事实表述；实现完成并核验一致后清理过渡差异，只保留统一的当前形式。
- **CLI**：只负责 `init` 和版本查询；项目理解、核验、规则判断与状态更新由 agent 完成。

## 当前项目级约束

- 核心 CLI 支持 Python 3.10 及以上，并只依赖 Python 标准库；打包产物必须包含全部项目模板。
- `init` 必须幂等，保留用户内容、项目事实、数据、结果和 Git 状态；只维护受管理区块、缺失入口和缺失标准章节。
- 受管理 marker 缺失、重复或顺序损坏时必须停止，不能静默生成第二套协议。
- 默认只创建 `AGENTS.md`、`CLAUDE.md`、`agent-docs/project.md` 和 `agent-docs/state.md`；`checkpoint.md` 与 `decisions.md` 只按需存在，不新增默认控制文档。
- 用户项目级意图和规则不得写入受管理区块；当前权威位置是 `agent-docs/project.md` 或其中登记的项目来源。
- 当前任务要求留在对话或活动 checkpoint，不复制到 `state.md`；只有项目级信息进入 `project.md`，范围不明确且会影响未来行为时才询问用户。
- 候选信息、模型推断和外部输出在核验前不是项目事实；被替换或废止的规则和状态不得保留在默认读取控制面。
- 普通讨论、分析、建议、搜索结果和任务输出本身不触发持久化；无持久化事件时不得为了同步而修改控制面。
- 持久化修改前重新读取目标文件和相关真实来源，发现外部变化时基于最新版合并并重新判断冲突，不得用旧上下文覆盖。
- 只有写入并重新读取核验成功后才能说明内容已持久化；明确的持久化请求失败时必须向用户说明。
- 不以文档长度为由压缩或删除仍然有效的知识；快速启动依靠当前状态、权威路由和按需读取完整来源。
- 同一 worktree 只允许一个未完成写任务；checkpoint 是该任务契约的唯一权威，`state.md` 不复制其内容；暂停任务保留 checkpoint，另一写任务使用独立 worktree，只读任务可以共存。
- CLI、插件 manifest、README 和测试中的基础版本必须一致；插件内容变化后刷新 cachebuster 并重新安装，新会话才加载新 skill。
- 不引入运行时自动化、后台扫描、任务数据库或额外默认读取文档。

## 项目结构与入口

> 登记稳定来源的权威范围和读取或复核条件，不维护文件清单。知识可以完整保存在项目来源中，不因控制面轻量而强制压缩。

| 目录或来源 | 权威范围 | 读取或复核条件 |
|---|---|---|
| `plugins/project-continuity/` | Codex 插件、`project-continuity` skill、CLI 核心实现和项目模板的主要来源 | plugin/skill 校验、CLI 行为、模板更新、cachebuster 和已有项目重新 `init` 的需要 |

| `scripts/` | standalone zipapp 等开发和发布辅助脚本 | 打包内容、入口点和目标平台执行权限 |
| `bin/` | 从源码运行 CLI 的跨平台启动器 | WSL/Linux 与 Windows 调用路径和退出码 |
| `.agents/plugins/` | 本地 Codex marketplace 定义 | 插件源路径、marketplace 名称和安装策略 |

| 仓库根目录 | README、Python 包元数据、许可证和项目级 agent 入口 | CLI/插件版本、安装说明、发布命令和当前控制面一致性 |
